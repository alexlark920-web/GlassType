# Геометрия и точность ввода — 1.6

## Анализ и границы изменения

Проект сохранён: два target UIKit, отдельный UIInputViewController, локальный
KeyboardCore в SPM, существующие InputState/темы/настройки/автозамена/удержания.
Ранее каждый горизонтальный UIStackView растягивал свои клавиши независимо.
Визуальный отступ был внутри UIButton; отдельного координатного распознавателя
не было. Это мешало согласовать смещения рядов, свайп и будущую калибровку.

Теперь Auto Layout размещает панель подсказок и одну KeyboardTouchSurface.
Поверхность размещает прежние кнопки по неизменяемой KeyboardGeometry.
Код действий кнопок, Shift/Caps, повтор Backspace, специальные страницы,
попапы, доступность, курсор и языковые свайпы пробела сохранены.

## Геометрия

Каждая клавиша имеет slotFrame (UIView), visualFrame (плашка), touchFrame
(базовая ячейка без пробелов). Все размеры вычисляются из доступных bounds после
safe area; используются points, а не физические пиксели. Четыре ряда делят
доступную высоту. Ширина определяется самым длинным рядом выбранной раскладки.
Второй буквенный ряд смещён на половину шага; Shift и Backspace занимают остаток
третьего ряда. Нижний ряд имеет веса и учитывает обязательную системную клавишу.
Горизонтальные поля коротких рядов принадлежат крайним клавишам.

Плашки немного шире относительно версии 1.5; общая базовая высота увеличена на
5%. Видимые промежутки сохранены, область касания от них не зависит.
Перемещение/подпрыгивание плашки не перемещает хитбокс.

## Распознавание

KeyboardTouchSurface.hitTest вызывает единственный TouchRecognizer. Он возвращает
один UIButton. Никаких пересекающихся увеличенных UIButton и перехватывающего
ввод overlay нет. UIButton.point(inside:) использует тот же решатель для выхода
и возвращения пальца в зону. Решение символа фиксируется при начале касания;
перетаскивание на другую букву не превращается в два нажатия. Долгое удержание
или распознанный свайп отменяет обычное нажатие средствами UIKit.

Для букв/цифр/пунктуации вычисляются расстояния до центров соседних клавиш в
единицах шага ряда. Геометрический вес — exp(-0.5 * ((dx/0.34)^2+(dy/0.32)^2)).
Нормированные веса дают реальные вероятности и три лучших альтернативы.
Точная ничья разрешается постоянным индексом раскладки. Функциональные клавиши
защищены собственными базовыми ячейками, поэтому языковая вероятность не может
превратить букву в Backspace или Enter. За внешней границей ввода нет;
точная правая/нижняя граница принадлежит крайней клавише.

CharacterLanguagePrior — интерфейс для будущей языковой модели. Геометрическая,
языковая и итоговая вероятности возвращаются отдельно; вес языковой оценки
ограничен. В текущем интерфейсе вес равен нулю, языковая модель не имитируется.
Новый слой только выбирает текущее нажатие. Уже введённый текст он не меняет.
Автозамена остаётся отдельным существующим механизмом с настройкой и отменой.

## Адаптация и приватность

Адаптация выключена по умолчанию. Если включена, учитываются короткие устойчивые
буквенные нажатия с высокой геометрической уверенностью (>=0.76), малым движением
и отклонением не больше 0.42 шага. Свайпы, удержания, функциональные клавиши,
редактор словаря, выделение, отсутствующий контекст, secure/URL/email/числовые
поля и поля с запретом коррекции исключаются. iOS обычно сама заменяет стороннюю
клавиатуру в secure-полях; код дополнительно проверяет secureTextEntry.

Хранятся только version и две группы чисел: count, meanX/Y, varianceSumX/Y для
портрета и альбома. Нет ID клавиш, букв, текста, документов, временных меток,
истории координат или сетевой передачи. Среднее и дисперсия обновляются по
алгоритму Welford; после 4096 наблюдений — ограниченное скользящее обновление.
Коррекция начинается после 32 образцов, нарастает постепенно и ограничена 0.18
шага. Шум уменьшает её влияние. Запись JSON выполняется пачками по 64 и при
скрытии клавиатуры, в личном sandbox расширения; Full Access не требуется.
Границы не меняются посреди активного касания. Отключение прекращает накопление
и применение; отдельная кнопка удаляет обе группы статистики.

Это консервативная оценка общего смещения, а не знание намерения пользователя.
Без явной разметки система не может достоверно определить ошибочную букву;
она не обучается на исправлениях сообщений и не строит персональный словарь.

## Отладка и производительность

Настройки приложения GlassType → «Адаптация касаний» → «Показать зоны касаний».
Полигоны получены пересечением геометрических областей Вороного с защищёнными
ячейками функций. Они соответствуют действующему распознавателю, включая
калибровку; точки отмечают визуальные центры. Overlay не принимает касания.
Полигоны строятся только при включённой отладке и изменении раскладки/смещения.

Распознавание — O(N), N < 50; лучшие три кандидата хранятся в фиксированных
значениях. На каждое касание не создаются массивы кандидатов/сортировки/объекты
моделей. Для обычного ввода словари не сканируются геометрическим решателем.
Ряды не пересоздаются на каждой букве. Быстрая печать двумя пальцами остаётся
обычным UIButton multi-touch; второй палец отменяет только возможный glide.

Модульные тесты проверяют 312–844 pt, три языка, обе страницы символов, границы,
пустые/нечисловые bounds, вероятностные ничьи, смещения, независимость от плашек,
защиту функций, эквивалентность отладочных зон, сериализацию и быстрые серии.
Время, память расширения и ощущение набора надо дополнительно измерить на
физическом iPhone: тесты координат не воспроизводят реальную кожу/скорость пальца.

## Исправления непрерывного ввода и словари

GlideTouchRecognizer получает исходную точку, включая coalesced samples. Начало
определяется движением >=7 pt и переходом на другую буквенную клавишу, без
раннего запрета UIPan. Малое дрожание остаётся обычным tap. Полная траектория
сохраняется для декодирования, а видимый след содержит только последние 140 мс.
Декодирование выполняется на отдельной последовательной очереди; перед вставкой
повторно проверяются документ, контекст, выделение, язык и поколение ввода.

Встроены 48 416 EN, 48 771 RU, 27 340 UK слов с частотным порядком. Индекс начала
и конца строится по всему корпусу, затем идут геометрический отбор и DTW для
лучших кандидатов. Частотный prior используется только для ранжирования слов
glide; он не подменяет CharacterLanguagePrior в распознавании одиночных касаний.
Украинская часть частотного корпуса отфильтрована Hunspell-совместимой проверкой во время подготовки. Частотные списки EN/RU расширены с 30 тысяч до полного лимита 50 тысяч исходных записей; после языковой фильтрации остаётся около 48 тысяч форм каждого языка, включая дополнительные склонения и времена из исходного корпуса. Отдельно добавлены 197 проверенных современных терминов и словоформ, которых нет в расширенном частотном списке. Тот же корпус используется строкой подсказок через индекс первых двух букв; UI читает только готовый снимок и не ждёт фоновой загрузки.
Языковые ё/ґ сводятся к базовой клавише; внутренний апостроф сохраняется в слове.
Это базовый офлайн-декодер без большой нейросети/контекстной LM. Полнота словарей
и качество произвольных траекторий не равны коммерческим клавиатурам.

Ресурсы CC BY-SA 4.0, атрибуция/полные лицензии включены в SPM bundle; код MIT.
Scripts/build_lexicons.py воспроизводит фильтрацию из источников с проверкой
Git blob hashes. `Scripts/package_source.py` автоматически создаёт версионированный ZIP исходников из канонических файлов репозитория.
При сборке IPA проверяется наличие трёх словарей непосредственно в расширении.
