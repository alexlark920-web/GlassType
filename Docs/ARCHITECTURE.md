# Архитектура и порядок реализации

## Структура

- `App/`: UIKit-приложение, подключение клавиатуры, настройки, поле проверки.
- `Keyboard/`: отдельный `UIInputViewController`, UIKit-ряды, жесты, визуальная тема.
- `Core/`: локальный Swift Package, без зависимостей; раскладки EN/RU/UK, Shift/Caps Lock, протокол подсказок и локальная реализация.
- `Shared/`: настройки и идентификатор App Group, компилируются в оба target.
- `GlassType.xcodeproj/`: приложение, расширение, embed-фаза, зависимость между target, локальный SPM-пакет, общая схема.
- `Core/Tests/`: XCTest для поведения ядра; не требуют UIKit.
- `Scripts/`: проверка структуры, проверки на Mac, создание неподписанной IPA.

## Решения

1. Состояние ввода не зависит от UIKit. Контроллер выполняет `insertText` и `deleteBackward` через системный `textDocumentProxy`; доступа к полному документу не предполагается.
2. Раскладки описываются данными. Украинская `ґ` и русская `ё` доступны удержанием; апостроф — на странице символов. Отдельная языковая кнопка переключает EN/RU/UK, глобус вызывает системный список.
3. Геометрия — Auto Layout: четыре ряда делят высоту поровну, ширина клавиш зависит от числа символов. Без фиксированных координат iPhone; учтены safe area и смена ориентации. Высота портрет/альбом: 278/202 pt плюс нижний inset. Альбомные клавиши ниже 44 pt, как у плотных системных раскладок; это требует проверки доступности на устройстве.
4. `KeyboardTheme` содержит семантические цвета и скругления. Material 3 служит визуальным ориентиром: мягкие клавиши, акцент на управляющих элементах, адаптивные цвета. Стеклянная поверхность — `UIVisualEffectView(.systemThinMaterial)`. Это не заявление об использовании или точном воспроизведении Liquid Glass API iOS 27. На новой SDK можно заменить поверхность, не изменяя движок.
5. `SuggestionProvider` — синхронный интерфейс для небольшого локального движка. Текущий MVP предлагает до трёх слов из демонстрационного словаря; полноценного словаря и автоматической коррекции ещё нет. Перед заменой повторно сверяется текущий префикс и отсутствие выделения. Не сохраняет набранные слова.
6. Общие настройки записывает приложение; расширение читает при появлении. Без полного доступа использует значения по умолчанию и не обращается к App Group. `RequestsOpenAccess = true` позволяет пользователю разрешить общие настройки; это не обязательное условие ввода. При смене настроек закройте и снова откройте клавиатуру.
7. Никаких сетевых библиотек, загрузок, аналитики, изображений, шрифтов или моделей. Текущий движок ограничивает поиск последними 64 символами. Перестройка рядов происходит при смене языка/страницы/настроек, обычный ввод обновляет подписи и небольшую строку подсказок. Таймер удержания удаления прекращается на отпускании, отмене и скрытии.
8. Deployment target — iOS 16. Это позволяет использовать известные UIKit API и запускать проект на более новых iOS. Для подтверждения iOS 27 необходимы соответствующий Xcode/SDK, симулятор и устройство; в Linux это проверить нельзя.

## Ограничения платформы

- iOS может заменить стороннюю клавиатуру системной в защищённых полях и некоторых телефонных полях; приложение-хост вправе запретить extensions.
- Расширение получает только ограниченный контекст. Он может быть `nil`; в этом случае подсказки отключаются, а ввод продолжает работать.
- Нельзя гарантировать вызов конкретного действия приложения по кнопке Return: расширение вставляет `\n`, а приложение-хост определяет реакцию.
- Здесь нет диктовки, свайп-ввода, системной автокоррекции, доступа к микрофону, clipboard или эмодзи-каталога. Числа и знаки доступны через `?123`; отдельных telephone/decimal-pad раскладок в MVP нет.
- Расширение не рисует за пределами своего view: popup зажимается внутри его границ. Для выбора варианта удерживайте клавишу, сдвигайте палец по горизонтали, затем отпустите. VoiceOver получает дополнительные действия для альтернатив.
- Система ограничивает память и может завершать процесс. Публичного универсального безопасного лимита нет; расход памяти и утечки нужно измерять Instruments на устройстве.
- Full Access — системное разрешение с широкими возможностями, хотя этот проект не содержит сетевого кода. App Group при переподписи SideStore может зависеть от типа аккаунта и provisioning. Без доступной группы клавиатура должна проверяться отдельно с настройками по умолчанию.

## Последовательность реализации

1. Зафиксировать границы MVP и ограничения платформы (этот документ).
2. Создать приложение, extension, plists, entitlements, embed-фазу и локальный пакет.
3. Реализовать раскладки, состояние ввода, подсказки и тесты ядра.
4. Подключить UIKit-контроллер, Shift/Caps Lock, Backspace с повтором, языки, символы и удержание.
5. Подключить темы, адаптивные ряды и настройки.
6. Проверить файлы проекта здесь; на Mac запустить XCTest, simulator build и archive.
7. Подписать/переподписать IPA, установить через SideStore, выполнить матрицу проверки устройства.

## Честный статус проверки

Исходники и Xcode-проект созданы. В рабочей среде отсутствуют `swift`, `xcodebuild`, Apple SDK и симулятор. Проверка структуры не доказывает компиляцию Swift, совместимость SDK, отсутствие Auto Layout warnings или корректную работу на устройстве. См. `VALIDATION.md`.
